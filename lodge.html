The control chat

/agentsLists the agents you can see, with a status button for each. A new chat’s Start button sends it too.
/status <agent>Which backends are running and since when, whether each is logged in, and when the model last ran a command as the executor.
/start · /stop · /restartStart, stop or restart an agent.
/auth <agent> [backend]Log an agent in: the bot sends the vendor’s login URL, and you reply with the code.
/upgrade <agent> · /upgrade relayBuild the signed release in the shared Nix store and move the agent onto it; or upgrade the relay itself.

Without an agent name, the bot offers buttons, one per agent. Owners are set per agent or for the whole fleet, by Telegram user id. Plain text gets no answer.

The design: Linux does the isolating

Every agent is three ordinary Linux users. The agent, <agent>, holds the model credentials and runs Claude Code and Antigravity. The executor, <agent>-exe, runs every shell command the model issues and holds no credentials. The manager, <agent>-mgr, is the agent’s side of the control chat. Two more accounts serve the whole host: lodge-relay holds the Telegram bot and routes owners’ commands, and lodge-store builds releases into a shared Nix store. Root installs.

The agent reaches its executor only through sudo, to run one command. The command text travels in an environment variable, so sudo’s log does not record it. The manager and the agent talk through a directory, not a shell. Nothing here is a novel security mechanism, and nothing is a virtual machine: it is the operating system’s own permission model, applied with care, so the agents can still build and test on hardware you never have to touch from your laptop.

Claude Code and Antigravity, unmodified

Lodge does not replace a vendor’s agent with its own. Every agent carries Claude Code and Antigravity (Google’s agy CLI), unmodified, and runs each one that is logged in.

Antigravity is also wired into Claude. A Claude session can start sessions with Antigravity and use them the way a person uses Antigravity’s own interface: long-running conversations of many turns. Claude sends messages, reads the replies, and chooses the model each conversation runs on. That lets Claude run a task from the top and delegate parts of it to Antigravity, deciding how much context each session gets, how large a part of the task it takes on, and which Antigravity model suits it.

How it is built

One Go binary, lodge, is every daemon, every installer step and the shell shim. It is built with Nix and uses a small set of well-known libraries: cobra, go-telegram/bot, the MCP Go SDK and golang.org/x. MIT licence.

Releases build from git tags whose commits are signed. Root and the store both pin the one signing key the host was first installed with (Nix verifyCommit), so an upgrade runs only code signed by that key. /upgrade from the chat builds the release in the shared Nix store and moves the agent onto it. Each executor has its own Nix store, since the shared one is read-only to the model’s commands.

Installing on Ubuntu is one command as root: install.sh with a release tag and the agent’s name. It sets up a Nix of root’s own, pinned by sha256, then runs lodge install.
